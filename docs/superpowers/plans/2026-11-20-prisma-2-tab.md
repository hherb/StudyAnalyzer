# PRISMA 2: the PRISMA 2020 tab — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a *PRISMA* tab beside *PICO*. It appraises a systematic review
against PRISMA 2020 and leads with the key gaps, then the checklist by
section. Every judgement is backed by the paper's own highlighted spans.
Each part of a run is stored as it finishes, an interrupted run can be
continued, and every run is kept.

**Architecture:** bmlib's `Prisma2020Agent` (plan PRISMA 1) asks, splits and
checks quotes. This repository does the rest:
- it sizes the budget, drives the parts (retries, halving a part cut off,
  re-asking missing items, re-checking condensed key gaps) and stores each
  part
- it shows the run

The layout is as for PICO: logic in `crates/studyanalyzer-core` (with a faked
`JsonChat`), thin commands in `src-tauri`, and Svelte 5 in `src/`. Spans are
code points in Rust and UTF-16 at the boundary (`view.rs`).

**Tech Stack:** Rust 2021, Tauri 2, bmlib at the PRISMA 1 merge commit,
Svelte 5, TypeScript, Vite, vitest. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-18-prisma2020-tab-design.md`
(all of it). The pattern is plan `2026-11-03-phase2c-pico.md` and the code it
built (`pico.rs`, `pico_store.rs`, `PicoTab.svelte`). Read both first.

## Global Constraints

- Everything in phase 2c's Global Constraints still holds:
  - the gates before every commit (CLAUDE.md § Gates)
  - constants in `config.rs`, doc comments, and tests on outward-facing items
  - no truncation, and every error logged and shown
  - never the abstract alone: the abstract feeds only the suitability check
  - a citation shows `canonical.span_text`, never the model's copy
  - the highlights: current `var(--hl-current)`, others `var(--hl-past)`
  - the phone switch below `PHONE_BREAKPOINT_PX`
  - with no model chosen, a run is `needs_model`
- A new command goes in `handler()`, `commands()`, `RETURN_TYPES`, `api.ts`
  and the vitest call list together.
- Labels shown to the user, exactly:
  - judgements: `reported` → *Reported*, `partly_reported` → *Partly
    reported*, `not_reported` → *Not reported*, `reported_elsewhere` →
    *Reported elsewhere, not checked*, `not_applicable` → *Not applicable*
  - unbacked: *Not reported: the model's claim could not be checked against
    the paper*
  - condensed: *Judged from a condensed paper*
  - re-checked: *Checked again on a condensation for this item*
  - an item no part has assessed yet: *Not assessed*
- There is **no percentage or category anywhere.** Key gaps are a count:
  *{n} of {k} key items are not or only partly reported*, plus *{m} key items
  rely on material outside the paper* when `m > 0`. An incomplete run shows
  *Not complete* in place of the count.
- The footer, exactly: *PRISMA 2020 checklist © Page MJ et al., BMJ
  2021;372:n71, CC BY 4.0.*
- Judgement chips carry their text, never colour alone.

## Review Focus

1. **A run stopped or failed at part 4 of 6.** Parts 1–3 are kept and shown,
   with the rest *Not assessed*. *Continue* runs only 4–6 on the run's own
   model and text, even after the user chose another model. Tests: Task 3
   `stop_keeps_finished_parts`, `failure_keeps_finished_parts`,
   `continue_runs_only_pending`, `continue_uses_run_model`; Task 5
   `continueOffered`.
2. **A long paper on a small window.** Each part is condensed with its own
   query and never cut. A key item judged *not reported* is re-checked once,
   on its own condensation. Tests: Task 3 `condensed_key_gap_is_rechecked`,
   `recheck_keeps_first_judgement`, `non_key_condensed_is_noted`,
   `whole_paper_needs_no_recheck`.
3. **A reply cut off at its limit, or one that leaves out an item.** A cut
   reply halves the part, down to single items. A missing item is re-asked
   once, then the part fails, naming the item. Tests: Task 3
   `truncated_part_is_halved`, `single_item_truncated_fails`,
   `missing_item_reasked_once`, `still_missing_fails_part`.
4. **A paper that is not a systematic review.** The tab says so with the type
   and rationale and offers *Run anyway*. It never auto-runs the assessment
   after a not-suitable check. Tests: Task 3 `not_suitable_stores_check_only`;
   Task 5 `shouldAutoRun`, `offerRunAnyway`.
5. **A converter bump after a PRISMA run.** A text with PRISMA citations is
   never re-derived, and an earlier run's highlights never move. Tests: Task 2
   `text_with_prisma_citations_not_rederived`; Task 4
   `earlier_run_uses_its_text`.

  - `pub enum PrismaEvent` (serde `kind`, snake_case):

    `of` counts the parts pending when the call started.
  - `pub enum PrismaRunError`: `PicoRunError`'s variants, plus
    `ReplyTooSmall { item: String }`, which reads *The model's reply room is
    too small for a PRISMA item; choose another model.*
  - `pub fn budget_chars(window: Option<u64>, reply: u64, title: &str, plan: &[PartPlan]) -> Option<usize>`:
    `pico::budget_chars` with the plan's longest `part_prompt_chars` in place of
    PICO's longest prompt. It returns `None` under `PRISMA_MIN_BUDGET_CHARS`.
  - `pub fn run_prisma(ctx: &mut PrismaContext, paper: &PaperId, force: bool, stop: &AtomicBool) -> Result<i64, PrismaRunError>`:
    this makes a new run.
  - `pub fn continue_prisma(ctx: &mut PrismaContext, run_id: i64, stop: &AtomicBool) -> Result<i64, PrismaRunError>`:
    this runs the run's pending parts on **its own** canonical text. The
    command passes the run's model.

- [ ] **Step 1: Write the failing tests**, with a scripted `JsonChat` and a
  fake `QueryCondenser`, as in `pico.rs`'s tests:
  - The suitability flow:
    - `not_suitable_stores_check_only`
    - `force_skips_check`
    - `check_reads_abstract_when_present`
  - The split:
    - `plan_follows_reply_budget`: `reply_tokens` maps to the part count from
      `plan_parts`.
    - `item_too_large_is_reply_too_small`: refused before any call.
    - `too_long_window_is_refused`
  - Stop and failure:
    - `stop_keeps_finished_parts`: stopped after part 2 of 4, so parts 1–2 are
      `done` and 3–4 `pending`, the run is `incomplete`, and the result is
      `Cancelled`.
    - `reply_during_stop_is_kept`: spec §7.
    - `failure_keeps_finished_parts`: a `RequestFailed` that outlives the
      retries leaves the part `failed`, the earlier parts kept, and the run
      `incomplete`.
    - `request_failed_is_retried`, `stopped_is_not_retried`
  - Continue:
    - `continue_runs_only_pending`
    - `continue_uses_run_text`: a newer canonical text exists, and the quotes
      are located in the run's own.
  - Cut replies and missing items:
    - `truncated_part_is_halved`: then each half is asked.
    - `single_item_truncated_fails`: the part fails with `truncated`.
    - `missing_item_reasked_once`: a `missing` part with that item.
    - `still_missing_fails_part`: the error names the item.
  - Condensation and re-checks:
    - `condensed_key_gap_is_rechecked`: a condensed part judges 7
      `not_reported`, so one `recheck` part for `["7"]` follows, whose query is
      `part_query([7])`.
    - `recheck_keeps_first_judgement`
    - `non_key_condensed_is_noted`: items are stored `condensed = 1`, with no
      re-check.
    - `whole_paper_needs_no_recheck`
  - Events:
    - `events_name_each_part`: `Part { index, of, label }` in order, with
      `Rechecking` before a re-check.
- [ ] **Step 2: Run them.** Expected: FAIL.
- [ ] **Step 3: Implement.** The loop shape (the one algorithm the tests leave
  open):

```text
run_prisma: full_text → (check unless force; not suitable → save_not_suitable, return)
            → plan = plan_parts(CHECKLIST, reply_chars) → budget_chars → create_run → drive
continue:   load run → its canonical text → drive
drive(run): while let Some(part) = pending_parts(run).first():
              cancelled(stop)?            // before each part; finished parts stay
              emit Part
              prepared = agent.prepare_part(title, text, part.items)      // once per part
              match with_backoff(.., agent.assess_part(&prepared, ..)):
                Ok(a)  → save_part(a, condensed = prepared.condensed_from_chars().is_some())
                         if !a.missing.is_empty(): reasks left? add_part("missing") : fail_part(missing)
                         if part.kind == "recheck": apply_recheck
                         else if condensed: for each key item with judgement NotReported: add_part("recheck",[id])
                Err(Truncated) if part.items.len() > 1 → split_part(halves)
                Err(Stopped)/stop set → return Cancelled
                Err(e) → fail_part(e.kind(), e); return Err
            finish_run(run)
```

  Log as `run_pico` does (info on a stop, warn on a model failure, error on a
  store failure).
